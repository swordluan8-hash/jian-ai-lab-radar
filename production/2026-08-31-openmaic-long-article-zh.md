# OpenMAIC 真实导出了一堂课：7039 项通过，45 项失败全部保留

8 月 31 日，GitHub Trending 全球榜首 OpenMAIC 进入剑的 AI 实验室。我们没有先调用付费模型做一段漂亮演示，而是从真实安装开始，跑完整测试、生产构建和 PPTX 导出，最后留下了一份别人能够下载复查的四页中文课件。

OpenMAIC 来自清华大学团队。它希望把一个主题或一份资料变成互动课堂，内容可以包含课件、测验、互动网页、项目式学习、白板、语音和多智能体讨论。这个方向对教师、企业培训团队和知识型创作者很直接：原本需要人工整理结构、制作幻灯片、设计测验和组织课堂互动的工作，可以尝试压进同一套生成与导出流程。

但功能介绍不能代替实验。

## 首轮安装先失败

实验使用的源码固定在提交 `dfebbcf33f3a56064129903faeab70a9e4243146`。首轮锁文件安装中，仓库供应链检查通过，OpenMAIC 工作区包也完成编译；pnpm 11 随后发现第三方构建许可仍是占位配置，因此没有替用户自动放行安装脚本，命令以退出码 1 结束。

这条失败没有删除，也没有改写成“环境问题所以不算”。

第二轮只放行本次 PPTX 导出路径需要的 `esbuild`，其他第三方安装脚本继续禁用。重新安装后退出 0，七个 OpenMAIC 工作区包完成编译。整个过程没有填写模型密钥，也没有产生模型 API 费用。

## 完整测试不是全绿

完整测试共运行 7163 项：

- 7039 项通过
- 45 项失败
- 79 项跳过

三个测试文件没有通过。绝大多数失败来自浏览器并发存储测试的五秒超时，另有一个远程图片 PPTX 测试超时。

因此，实验不能写成“7163 项全部通过”。同样，也不能因为 45 项失败就抹掉已经通过的 7039 项。实验田保留完整数字和失败原因，再把今天真正使用的 PPTX 导出路径单独复测。

文本内容、文本格式和背景三个导出专项文件共五项测试，五项全部通过。

## 生产构建完成

Next.js 生产构建退出 0，生成 52 个静态页面。构建过程中留下两条与 Edge Runtime 中 `process.once` 有关的警告，这些警告同样进入实验报告，没有从结论中隐藏。

这一步说明代码可以完成正式构建，但不等于所有运行时集成和外部模型服务已经验证。

## 最终成果不是演示图

收成区没有另画一张与项目无关的信息图冒充成果。

实验脚本直接调用 OpenMAIC 生产代码中的 `buildPptxBlob`，导出了一堂四页中文微课，主题是“怎样判断 GitHub Trending 项目值不值得用”。

四页内容分别包括：

1. 要解决的问题。
2. 项目来源、安装和成果。
3. OpenMAIC 的完整测试数字。
4. 一道收尾小测验。

导出的 PPTX 为 79,985 字节，可以在 PowerPoint 或 Keynote 中继续编辑。随后将文件解包，确认四个幻灯片 XML 均存在，并检查四段预设文字是否真正写入文件结构。文件 SHA-256 为：

`797c657437ad6e96923604c12351295af279c6f8b6ddeffd231203bfe9c93e1e`

## 对使用者真正有用的部分

这次已经验证三件事：

- OpenMAIC 的代码能够完成安装和生产构建。
- PPTX 专项导出路径可以离线工作。
- 项目自己的生产导出器能够留下可下载、可编辑、可复查的真实成果。

对于教师和培训团队，这意味着它至少不是只能观看演示的视频项目。导出的幻灯片能够进入现有办公流程继续修改，而不是被锁在一个只能观看的网页里。

对于内容创作者，它的潜在替代价值是把“找资料、搭结构、做课件、加测验和导出文件”集中到同一条工作流。但这部分价值要完全成立，还必须继续验证真实模型生成质量和人工审稿成本。

## 没有验证的部分

本次没有验证：

- 多智能体生成一堂完整课程的质量。
- TTS 语音。
- 视频生成。
- 实时课堂互动。
- 商业模型提供商集成。
- 长时间运行稳定性。

这些能力需要真实模型、资料、提示词和外部媒体服务。没有得到付费许可以前，不调用付费 API，也不把 README 中的能力写成实验结果。

## 结论

OpenMAIC 在本次零付费实验中完成了安装、生产构建和真实 PPTX 导出。7039 项测试通过，45 项失败和 79 项跳过完整保留。它已经证明自己能留下一个可编辑成果，但还没有证明多智能体课程生成能够稳定达到发布质量。
